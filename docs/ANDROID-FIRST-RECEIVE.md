# Android 첫 공유 수신 지연 — 17.4.1

백업 불러오기는 공유 참여의 필수 단계가 아닙니다. 같은 그룹의 operations 기록을 읽어 전체 의존 관계를 검증한 뒤 자동으로 앱에 반영합니다. readable Markdown은 읽기용 결과물입니다.

실제 진단에서 첫 처리 주기가 시작되고 600개 중 597번째 JSON을 읽는 동안 완료 시각은 비어 있었습니다. 시작 시각과 진단 시각 간 약 45분이 지났지만, 앱의 백그라운드·절전 시간을 포함할 수 있어 45분 전체를 파일 읽기 시간으로 단정하지 않습니다. 마지막 요청의 경과 시간 821ms만으로 해당 파일이 멈췄다고도 판단하지 않습니다.

코드에서 확인한 비용은 JSON마다 SAF로 상위 폴더와 operations 폴더 목록을 다시 조회하는 점입니다. 첫 수신을 끝내기 전에는 검증한 기록도 저장하지 않아 종료되면 다시 읽을 수 있었습니다.

17.4.1은 한 처리 주기 안에서 읽기 전용 문서 주소 목록을 재사용합니다. 파일 내용은 매번 실제로 읽고 검증합니다. 새 이름이 없으면 목록을 새로 조회하고, 주소가 사라졌으면 다시 조회해 재시도합니다. 주기가 바뀌거나 앱이 직접 파일을 변경하면 목록을 비웁니다. 쓰기 전 검증은 이 캐시를 사용하지 않습니다.

검증한 수신 기록은 32개마다 로컬에 중간 저장합니다. 전체 확인 전에는 메모와 반영 기준을 바꾸지 않습니다. 재실행하면 저장한 기록은 건너뛰며, 다른 그룹의 기록은 여전히 분리합니다. 화면에도 읽는 기록 번호를 표시합니다.

검증은 600개 이름의 목록 조회 횟수, 늦게 도착한 파일, 주소 교체와 조회 실패, 첫 수신 중단 후 이어 읽기, 저장 실패 시 원본 보존, 실제 SAF 새 파일·최신 내용 읽기를 포함합니다. 실제 Galaxy Flip5의 개선 여부는 설치 후 첫 처리 주기 완료로 별도 확인해야 합니다.
