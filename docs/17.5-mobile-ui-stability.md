# 모두톡 17.5 모바일 화면 안정화 (배포 전 수정)

이번 수정은 `release/modutalk-v17.5.0`의 **모두톡 Obsidian 연동 화면**에만 적용합니다. Obsidian 코어나 Sync 프로토콜은 변경하지 않습니다.

## 수정 내용
- 모두톡 화면이 활성화되고 준비되었을 때만 호스트의 모바일 상단 제목줄과 하단 내비게이션을 숨깁니다.
- 모두톡 상단의 **Obsidian 메뉴** 버튼으로 즉시 복구하며, **전체 화면** 버튼으로 되돌릴 수 있습니다.
- 다른 노트/탭으로 이동하거나 모두톡 화면을 닫거나 플러그인을 해제하면 숨김 클래스를 제거합니다.
- 공유 폴더 선택 실패/파일 로딩 실패 시 기본 메뉴를 숨기지 않습니다.
- 플러그인 안의 파일 저장 상태는 연결·권한·오류 중심의 짧은 문구로 유지합니다. 실제 단계별 상태 원문은 기존 진단 데이터와 상태 툴팁에 보존합니다.
- 단독 Windows 및 Android 앱의 기존 동기화 상태 표시 방식은 변경하지 않습니다.

## 확인 절차
`node --test tests/modutalk-ui-stability.test.cjs`

자동 테스트는 화면 상태 전환, 메뉴 복구, 주요 상태 문구와 오류 표시, 기존 단독 앱 분기를 점검합니다.

실제 Galaxy Flip5의 Obsidian 앱에서 아래 항목을 추가 확인한 뒤 배포해야 합니다.

1. 모두톡 시작: 상단·하단 Obsidian 메뉴가 가려지되 메모 목록과 입력창이 정상 표시되는지
2. **Obsidian 메뉴** 버튼: 상·하단 메뉴 복귀, **전체 화면**: 다시 최소화
3. 다른 노트/탭으로 이동: 메뉴 자동 복구
4. 모두톡 닫기/플러그인 해제: 메뉴 자동 복구
5. 키보드 표시·숨김, 세로/가로 회전: 메모 작성창·마지막 메모가 가려지지 않는지
6. 반복 자동 동기화: 파일 저장 옆 문구가 단계별로 깜빡이지 않는지; 오류·접근 권한 문제는 보이는지
7. PC→휴대폰 및 휴대폰→PC 신규 메모 각각 1건 송수신, 댓글/사진 및 기존 메모 보존

### 배포 주의
이 브랜치는 수정 후보이며, Obsidian 및 Android 기기에서 실사용 UI를 직접 확인한 릴리스가 아닙니다. 기존 17.5 플러그인 폴더와 공유 그룹의 백업을 준비하고, 실제 배포 시 플러그인 `main.js`·`styles.css`·`app.html`을 함께 패키징해야 합니다. 동기화 기록이나 그룹 파일을 삭제하거나 재설정할 필요는 없습니다.
