# MemoTalk ↔ Obsidian: 동기화 정책 초안 (실험용)

> 상태 (2026-11-11): **개발 브랜치에 Windows 단방향 저장·중단 복구·검증 기반 구현. 실제 원격 전송과 Android 및 양방향 동기화는 미검증/미구현.**
> 개발: `feature/obsidian-bridge-prototype`. main·기존 배포본·실사용 vault 데이터는 변경하지 않음.
> 검증 기록과 후속 예상 기간: [OBSIDIAN-BRIDGE-VALIDATION.md](OBSIDIAN-BRIDGE-VALIDATION.md)
> 대상: Windows / Android 메모톡, Obsidian 보관함 안의 전용 하위 폴더, Obsidian Sync

## 사용자가 선택한 원칙

**어느 한쪽 기기에서 메모를 생성·수정·이동·이름 변경·삭제하면 다른 기기에도 반영한다.**
이를 즉시 반영 지향으로 구현한다. 다만 네트워크 연결과 Obsidian Sync 실행 상태에 따라 실제 원격 반영은 지연될 수 있다.

## 기존 v17.0.2 동작과 제약

- 메모톡의 원본 데이터는 앱 내부 저장소다.
- `shared/index.html`의 파일 미러링 기능은 앱 내부 데이터 → 선택된 로컬 폴더로 쓰는 **단방향** 기능이다.
- 변경 직후 기본 1,400ms의 지연 후 저장을 예약한다. 개발 브랜치에서는 파일 저장 메뉴에서 즉시 조절·초기화하고 로컬 설정을 유지한다. 이는 원격 전송 완료 시간이 아니다.
- 외부에서 기존 미러 파일을 고치거나 삭제하면 현재 코드는 `mirror_external` 오류를 내고 덮어쓰기를 중단한다.
- 현재 폴더 연결은 빈 폴더(또는 본인이 이전에 연결한 저장 폴더)를 요구한다.
- 파일 구조에는 개별 `.md`, 첨부파일, `manifest.json`, `.memotalk-file-index.json`, 변경 전 보관 파일이 포함된다.
- Android에서는 저장소 접근 권한 및 Obsidian 보관함 위치/접근 가능성에 대한 실기기 검증이 필요하다.

## 개발 브랜치에서 추가한 기반

- Windows 오류의 상대 경로·errno·syscall·쓰기 단계·임시 경로·대상 경로를 IPC 응답에 보존하고 로컬 진단 메뉴로 표시한다. 공개 서버로 오류나 메모를 보내지 않는다.
- 새 파일은 미리 0바이트로 만들지 않는다. 임시 파일 쓰기·flush·읽기 검증 후 게시하고, 기존 파일은 기준 바이트 비교와 검증된 이력 사본을 거쳐 갱신한다.
- 작업 기록을 먼저 저장하고 모든 파일을 재검증한 후 인덱스를 마지막에 기록한다. 변경된 파일은 재시도 시 자동으로 원본/작업 기록과 비교하며, 외부 수정은 중단한다.
- 기존 인덱스 없는 불완전 저장본은 읽기 비교 결과를 보여 주고 **새 빈 폴더**에 현재 앱 데이터로 복구한다. 다른 내용/추가 파일은 원본에 남으며 자동 가져오기·덮어쓰기·삭제하지 않는다.
- 이전 경로는 그대로 유지한다. 이동·삭제의 원격 전파는 아직 제공하지 않는다.
- `.memotalk-file-index.json`, `.memotalk-file-journal.json`, `.memotalk-history/`는 **기기 로컬용**이다. Obsidian Sync는 점으로 시작하는 일반 파일/폴더를 제외한다.
- 일반 파일 `memotalk-sync-state.json`은 출력 파일의 SHA-256과 snapshot ID를 담는다. 다른 기기는 로컬 dotfile 없이 완결성을 읽기 전용으로 검사할 수 있다. 이것은 원격 업로드 완료 확인이나 메모톡 자동 가져오기가 아니다.
- JSON manifest/state가 전송되도록 각 기기의 `Sync all other types`를 켜고, 전용 하위 폴더가 제외되지 않았는지 확인해야 한다. 사진·첨부도 유형 및 요금제 제한을 확인한다.
- 공식 근거: [Sync 설정과 숨김 파일 제외](https://obsidian.md/help/sync/settings), [암호화는 원격 vault에 적용됨](https://help.obsidian.md/Obsidian%20Sync/Security%20and%20privacy).

## 목표 작동

1. **초기 연결**: 기존 휴대폰/PC 데이터와 클라우드 폴더를 **합집합으로 비교**, 가져오기를 미리 보여 준 뒤 안전하게 병합한다. 빈 폴더나 이전 정보 부재를 삭제 신호로 해석하지 않는다. 기존 JSON 백업은 별도 보관한다.
2. **추가**: 고유한 메모 ID로 새 메모를 만들고 폴더에 쓰면, 다른 기기에서 파일 변경을 감지해 같은 ID로 받아들인다.
3. **수정**: 메모 ID를 유지한 채 버전을 갱신한다. 인과적으로 후속 버전임이 분명할 때만 자동 적용한다.
4. **동시 수정**: 양쪽에서 동일 메모를 오프라인으로 수정했거나 선후 관계가 불명확하면 자동 덮어쓰기 대신 원본 2개를 보존하고 충돌 사본을 만든다. 기기 시간만으로 승자를 정하지 않는다.
5. **삭제**: 파일이 단순히 사라진 것만으로 삭제를 전파하지 않는다. 사용자가 명시적으로 삭제하면 메모 ID의 삭제 표식(tombstone)을 기록하고 다른 기기의 휴지통으로 전파한다. 복구 가능 기간은 우선 30일로 제안하며 사용자 변경 가능하게 설계한다. 삭제 이후 오래된 기기의 메모가 자동 부활하지 않게 한다.
6. **이동/이름 변경**: 파일 경로가 달라져도 ID를 통해 동일 항목으로 인식한다.
7. **이미지/첨부**: 메모와 참조 첨부파일을 함께 이관하고, 전송 중 누락 시 기존 데이터에 손대지 않는다.
8. **안전**: 외부 변경 중간 읽기/쓰기 경합을 막고 임시 파일·검증 후 적용하며, 충돌 및 이전 내용은 역사 폴더에 보존한다. 개인 메모와 백업 파일은 공개 GitHub에 올리지 않는다.

## 구현 순서

- [ ] **1단계: 실제 두 기기 단방향 전송 검증** (로컬 저장/검증 기반은 구현·자동 테스트 완료) — Windows 메모톡에서 Obsidian 보관함 내부에 **빈 MemoTalk 하위 폴더**를 선택해 쓰기; Obsidian에서 `.md` 파일 읽기 및 Obsidian Sync로 다른 기기에 전파 확인. Obsidian에서 해당 파일을 편집하지 않는다.
- [ ] **2단계: 안전한 읽기 및 차이 미리보기** — 메모톡에 외부 폴더의 `manifest.json`과 `.md` 파일을 검사하고 가져오기/충돌을 미리 보여주는 기능 추가. 기존 내부 저장소를 바로 덮어쓰지 않는다.
- [ ] **3단계: 양방향 변경 적용** — 메모별 revision/operation ID 및 삭제 표식 도입, 충돌 사본 저장, 안전한 재시도.
- [ ] **4단계: Android 저장소 검증** — Android SAF와 Obsidian 보관함 폴더 접근, 앱 재시작/권한 갱신/오프라인 테스트.
- [ ] **5단계: 다중기기 검증** — 최초 서로 다른 메모 병합, 동시 수정, 삭제 전파, 복원, 이동, 첨부파일, 동기화 중단/재개를 테스트.

Obsidian **플러그인은 1~4단계에서 불필요하다면 만들지 않는다.** 메모톡의 읽기/쓰기 기능을 먼저 완성하고, Obsidian 내부에서 전용 편집 UI나 추가 편의 기능이 필요해질 때만 고려한다.

## 배포 보호

기존 v17.0.2 Release, main 브랜치, 기존 앱의 원본 데이터는 변경하지 않는다. 개발 브랜치에서 설계와 검증을 진행한다.
