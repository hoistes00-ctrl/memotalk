# Windows ↔ Android 같은 폴더로 메모 공유

개발 브랜치: `feature/obsidian-bridge-prototype`. 공유 시험판은 `17.1.0-sharing.3`입니다. main과 기존 정식 다운로드는 변경하지 않습니다.

## 무엇을 공유하나요?

두 **메모톡 앱**에서 추가·수정·삭제한 메모와 댓글·사진, 메모방·폴더 변경을 공유합니다. 처음 연결할 때는 양쪽의 기존 메모를 합집합으로 받아들이며, 다른 기기에 없다는 이유만으로 기존 메모를 삭제하지 않습니다.

같은 메모를 양쪽에서 동시에 고치면 두 원문을 모두 보존합니다. 표시할 버전은 기기 시계가 아니라 변경 이력에 따라 결정하고, 동시 변경은 충돌 보관함과 공유 변경 이력에서 확인합니다. 한 버전을 선택해 복원해도 다른 버전의 이력은 지우지 않습니다.

파일 전달은 Obsidian Sync가 맡습니다. Windows와 휴대폰에서 선택하는 실제 경로는 달라도, **같은 원격 vault의 같은 하위 폴더**여야 합니다.

## 먼저 준비할 것

1. 기존 앱의 JSON 백업을 별도로 저장하고 파일이 있는지 확인하세요. 실제 메모나 백업을 GitHub에 올리지 마세요.
2. Windows 공유 시험판을 설치/실행하기 전에 기존 Windows 메모톡을 종료하세요. 포터블도 같은 내부 저장소를 사용할 수 있습니다.
3. Android APK의 표시 이름은 **메모톡 공유 시험판 3**, 패키지는 `kr.memotalk.app.sharingpreview3`입니다. 기존 정식 앱을 덮어쓰지 않는 별도 앱입니다. 기존 Android 메모가 필요하면 원래 앱에서 JSON 백업을 내보내 이 시험판에 가져오세요. 원래 앱을 삭제할 필요는 없습니다.
4. 두 기기의 Obsidian을 같은 원격 vault에 연결하고 **Sync all other types**를 켜세요. 공유 하위 폴더가 제외 목록에 없어야 합니다.
5. 휴대폰의 vault는 시스템 폴더 선택 화면에서 접근 가능한 공유 저장소에 있어야 합니다. Android가 차단하는 다른 앱의 비공개 저장소에는 메모톡이 접근하지 않습니다.

## 휴대폰 또는 Windows에서 먼저 시작하기

1. 먼저 사용할 기기의 메모톡에 기존 JSON 백업을 가져오고 메모를 확인하세요.
2. Obsidian vault 안의 전용 하위 폴더를 고르세요. 이전 파일은 삭제하지 마세요.
3. **파일 저장 → Windows ↔ Android 양방향 공유 → 이 기기에서 새 공유 그룹 만들기**를 선택하세요. Android에서도 가능합니다.
4. 생성된 `memotalk-peer-group.json`과 `memotalk-peer-v1`을 Obsidian Sync가 다른 기기로 전달하도록 기다리세요.
5. 두 번째 기기에서는 **다른 기기의 공유 그룹 참여**로 같은 vault의 같은 하위 폴더를 선택하세요. 두 번째 기기에서도 새 그룹을 따로 만들지 마세요.
6. 처음에는 양쪽 메모가 함께 표시되며, 이후 수정은 양방향으로 반영됩니다. 동시 수정 원문은 모두 보존합니다.

`peer_group_not_downloaded`가 나오면 처음 시작하는 기기는 새 그룹 만들기를 선택하세요. 다른 기기에서 이미 만들었다면 JSON 전송과 제외 폴더 설정을 확인하고 그 그룹이 내려올 때까지 기다리세요. 서로 다른 두 그룹을 만드는 것으로 우회하지 마세요.

## 자동 반영과 실행 조건

메모톡은 열린 동안 기본 **3초 간격**으로 폴더를 확인하고, 수정 뒤 기본 **400ms** 대기 후 기록합니다. **공유 확인·반영 간격 조절**에서 즉시 변경·초기화할 수 있고 다음 실행에도 유지됩니다. 이 값은 원격 전송 시간 보장이 아닙니다.

**두 기기의 Obsidian도 실행 중이어야 합니다.** Obsidian이 종료되거나 휴대폰 절전 정책으로 중지되면 전송이 지연됩니다. 다시 Obsidian을 실행해 전송한 뒤 메모톡을 열면 이어서 반영합니다. 메모톡이 닫혀 있을 때 내부 메모를 백그라운드에서 바꾸는 기능은 아닙니다. [공식 Sync 실행 조건](https://obsidian.md/help/sync/faq).

상태 표시의 “양방향 주기 처리”는 이 기기에서 파일을 확인·반영했다는 뜻입니다. 다른 기기에 도착했는지는 상대 앱과 Obsidian Sync 상태에서 확인하세요.

## 충돌·삭제·복원

- 같은 원본에서 동시에 수정한 두 내용은 모두 이력 파일과 앱의 충돌 사본으로 남습니다.
- 메모의 이전 내용 버튼 또는 **공유 충돌·변경 이력 보기**에서 검토하고 원하는 버전으로 복원할 수 있습니다.
- 한쪽에서 삭제하고 다른 쪽에서 동시에 수정하면 수정된 원문과 삭제 의사를 모두 보존합니다. 단순히 파일이 없어졌다는 이유로 삭제를 전파하지 않습니다.
- 삭제한 메모의 이전 이력도 공유 변경 이력에서 선택해 복원할 수 있습니다. 이전 메모방이 없으면 메시지를 버리지 않고 복원 대기 메모방에 보존합니다.
- 공유 연결 해제는 파일이나 메모를 삭제하지 않습니다.

## Obsidian에서 읽기

`memotalk-peer-v1/readable`에는 각 변경 버전의 Markdown이 있고 사진은 `assets`에 있습니다. 이전 Markdown을 덮어쓰지 않으므로 여러 버전이 보일 수 있습니다. 이 파일들은 읽기용입니다. **Obsidian에서 Markdown을 직접 편집한 내용을 메모톡으로 가져오는 것은 이 앱 간 공유 기능과 별개이며 현재 지원하지 않습니다.**

## 오류가 있을 때

**공유 오류 진단**에서 코드·작업 단계·상대 경로를 확인하세요. 사진이나 이전 변경이 아직 내려오지 않았으면 기존 메모를 유지하고 다음 확인 때 재시도합니다. 편집 중에는 수신 적용을 잠시 미뤄 입력 내용을 보호합니다.

저장 공간 부족, 권한 회수, 파일 손상 또는 지원하지 않는 문서 제공자라면 성공으로 표시하지 않고 중단합니다. 진단에 개인 경로가 포함될 수 있으므로 공개 이슈에 그대로 붙이지 마세요.

## 저장 구조와 검증 범위

변경 이력과 사진은 고유한 이름의 새 파일로 추가합니다. 변경 ID는 SHA-256으로 검증하며, 부모 변경을 함께 기록해 전송 순서가 바뀌거나 같은 파일이 중복 수신되어도 처리할 수 있습니다. 시계가 틀린 기기의 내용으로 자동 덮어쓰지 않습니다. 작업 대기열은 IndexedDB에 먼저 보존하고, 내부 메모 반영은 저장 기준값 확인 후 한 번에 기록합니다.

점으로 시작하는 복구 파일이 Sync에서 제외되는 문제를 피하기 위해 기기 간 이력은 일반 파일에 저장합니다. 자동 이력 삭제는 하지 않습니다. 오래된 이력·사진도 용량을 차지하며 보관 정리는 별도 기능입니다. 로컬 앱 저장소가 부족하면 기존 데이터를 유지하고 오류를 표시합니다.

검증은 Windows/Linux 프로토콜·저장소 테스트, 두 분리된 앱 프로필의 UI 테스트, 실제 Android 에뮬레이터의 시스템 폴더 선택·SAF·WebView 왕복 시험, 실제 패키지 Windows EXE의 수신/송신 시험으로 구성됩니다. 각 CI 실행 결과로 완료 여부를 확인하며, 실사용 휴대폰과 실제 Obsidian 서버 전송의 결과를 에뮬레이터 결과로 대신 주장하지 않습니다.

## 시험 APK 서명

저장소에 소유자의 지속 서명키가 설정돼 있으면 별도 공유 시험판에도 그 서명키를 사용합니다. 없으면 별도 패키지의 디버그 서명을 사용합니다. 이 경우 다음 시험 APK가 같은 서명이 아닐 수 있어 덮어 설치가 거부될 수 있습니다. 기존 앱이나 시험판을 백업 없이 삭제하지 마세요. 정식 앱의 동일 서명 업데이트와는 다른 배포입니다.

## sharing.3 변경

휴대폰에서도 새 그룹을 만들 수 있습니다. 기존 폴더에 그룹 파일이 이미 있으면 그 ID로 참여하며 새 ID로 덮어쓰지 않습니다. 생성 도중 저장이 실패하면 연결을 활성화하지 않고 내부 메모와 원본 파일을 보존합니다. Android의 예전 저널 갱신 오류 방지도 유지됩니다.

새 APK는 메모톡 공유 시험판 3이며 이전 앱을 지우지 않고 함께 설치할 수 있습니다. 이전 앱에서 JSON 백업을 내보내 새 앱에 가져오세요. 임시 서명이므로 다음 시험판의 덮어 설치는 보장하지 않습니다.
