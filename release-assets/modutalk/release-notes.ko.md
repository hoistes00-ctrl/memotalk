# 모두톡 17.4.2

초기 변경 기록을 많이 보내는 동안 수신 확인이 늦어지는 문제를 개선했습니다. 진단에서 177개 기록을 보내는 동안 첫 처리가 완료되지 않았고, 보내기는 실제로 진행 중이었습니다. 17.4.1의 파일 목록 조회 개선만으로 이 대량 보내기 대기는 해결되지 않았습니다.

- 기본 4개씩 보낸 뒤 수신을 확인합니다. 보내기 큐가 남아 있어도 받은 수정 내용을 반영할 수 있습니다.
- 보낸 지점을 묶음마다 저장합니다. 뒤의 쓰기가 실패해도 성공한 앞부분은 재시작 때 건너뜁니다. 갑작스러운 종료로 마지막 묶음이 저장되지 않은 경우에만 안전하게 재확인합니다.
- 파일 저장 → 공유 확인·반영 간격 조절에서 묶음 수를 즉시 변경·저장·재시작 유지·기본값 복귀할 수 있습니다. 값은 다음 처리 주기부터 적용됩니다.
- 화면에 변경 기록 보내기와 남은 보내기 큐를 표시합니다. 큐가 남으면 저장 완료처럼 표시하지 않습니다.
- 진단에 진단 시각·앱 버전 제목·보내기 대기 수를 추가하고, 열린 시점의 값이므로 새로 고침이 필요하다고 안내합니다.
- Android의 실제 폴더 조회·문서 읽기·임시 쓰기·flush·sync·rename 단계를 읽기 전용으로 확인합니다. 이 조회는 파일 작업 대기열 뒤에 들어가지 않아 느린 기기 작업도 관찰할 수 있습니다. 메모 내용·권한 URI·토큰은 제외합니다.

검증은 91개 자동 검사, 177개 발신 중 새 수신 반영, 전송 실패 후 성공 구간 건너뛰기, 묶음 설정·재실행·복귀, 기존 충돌·중복 방·사진·백업 보존 및 Android SAF/WebView·Windows 설치형 왕복 검사를 포함합니다. 파일 쓰기 검증과 병합 전 백업은 유지했습니다.

기존 모두톡 수정판 위에 설치합니다. 앱 ID와 기존 Android 서명을 유지했습니다. 앱 삭제·백업 불러오기·공유 그룹 재생성은 필요하지 않습니다. 실제 Galaxy Flip5에서 이 버전의 최종 양방향 반영은 아직 확인 전입니다. 종료·절전·외부 Obsidian 전송 대기를 포함한 전체 실시간 전달을 자동 시험만으로 보장하지 않습니다.
